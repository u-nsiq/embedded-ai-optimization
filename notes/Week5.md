## 데이터 플로우 (Data Flow)

스케줄링은 AI 최적화 방법 중 **시스템 레벨**에서 최적화하는 방법이다. 이를 이해하기 위해 먼저 데이터 플로우 개념이 필요하다.

데이터 플로우란 AI 시스템에서 데이터가 어떻게 이동하고 처리되는지를 나타내는 흐름이다. 흐름을 명확히 이해하면 성능 최적화, 병목 해결, 유지 보수가 용이해진다.

### 핵심 개념

| 요소 | 설명 |
| --- | --- |
| 노드(Nodes) | 데이터가 처리되는 단위 또는 연산 |
| 엣지(Edges) | 노드 간 데이터가 이동하는 경로 |
| 입력과 출력(I/O) | 입력 데이터가 처리되어 최종 출력이 생성되는 과정 |
| 병렬성(Parallelism) | 자연스러운 병렬 처리 지원 |

### 구성 요소

- **데이터 소스(Source)**: 시스템으로 들어오는 입력점. 예) 사용자 입력, 센서 데이터, 외부 시스템
- **프로세스(Process)**: 데이터를 처리하는 단계. 예) 음성 인식 모델, 객체 탐지, 데이터 변환 및 필터링
- **데이터 플로우**: 시스템 내 데이터 이동 및 프로세스 간 전달 경로
- **데이터 저장소(Storage)**: 데이터가 저장 또는 일시 보관되는 곳. 예) DB, 파일 시스템, 메모리
- **데이터 싱크(Sink)**: 시스템의 출력점. 예) 출력 화면, 보고서, API 응답

### 단계

1. **데이터 수집 및 입력**: 외부에서 시스템으로 유입. 센서 데이터 수집 및 사용자 입력 텍스트 전달
2. **데이터 처리**: 데이터 변환 및 분석. 출력된 데이터 → 다음 프로세스의 입력으로 전달
3. **데이터 흐름 정의**: 프로세스 간 이동에 따른 플로우 구성 (동기식: 순차, 비동기식: 병렬)
4. **데이터 저장 및 캐싱**: 일시 또는 영구 저장. 외부 시스템에서 참조 가능
5. **데이터 출력 및 전송**: 화면 출력, 파일 저장, 다른 시스템으로 전송 (자율주행: 처리 결과 → 제어 모듈 → 제어 신호)

### 중요 특징

- **순차적 처리**: 데이터 처리 상태 추적 용이
- **병렬 처리**: 여러 프로세스 동시 실행 가능 → 처리 속도 대폭 향상
- **흐름 제어 및 관리**: 병목 파악 → 데이터 흐름이 원활하게 작동하도록 설계

### 데이터 플로우 유형

| 유형 | 특징 | 예시 |
| --- | --- | --- |
| 정적(Static Dataflow) | 실행 경로가 고정. 미리 결정된 경로 | 하드웨어 설계 |
| 동적(Dynamic Dataflow) | 실행 경로가 동적으로 변경. 데이터나 조건에 따라 달라짐 | 신호 처리, 데이터 스트리밍, 멀티미디어 처리 |

### 최적화 방법

- 병목 현상 최소화
- 데이터 병렬화
- 데이터 전처리 최적화
- 캐싱 사용

## 스케줄링 (Scheduling)

**스케줄링**: 시스템 자원을 여러 작업(Task)들 사이에서 효율적으로 할당하고 관리하는 프로세스.

작업을 언제 실행할지 결정하는 것이 성능과 신뢰성에 큰 영향을 미친다. 핵심 목표는 **시스템 자원의 최대 활용** + **여러 작업들의 효율적 실행**이다.

스케줄링 알고리즘은 우선순위, 실행 시간, 리소스 요구사항을 고려하여 작업이 적절한 시간에 처리되도록 조정한다.

### 스케줄링 알고리즘 종류

| 알고리즘 | 특징 | 핵심 키워드 |
| --- | --- | --- |
| FCFS (First Come First Serve) | 도착 순서대로 처리 | 비선점형, 단순 |
| 라운드 로빈 (Round Robin) | 동일한 시간 할당량(Time Quantum) 부여 후 순환 | 선점형, 공평성 |
| 우선순위 (Priority Scheduling) | 우선순위가 높은 작업 먼저 처리 | 선점형/비선점형, 기아 위험 |
| EDF (Earliest Deadline First) | 마감 시간이 가장 빠른 작업 먼저 처리 | 실시간, 동적 우선순위 |
| 동적 스케줄링 (Dynamic Scheduling) | 실시간으로 실행할 노드를 정해서 실행 | 유연성, 실시간 대응 |

---

## FCFS (First Come First Serve)

작업이 시스템에 도착하는 순서대로 처리하는 방식이다. 한 작업이 완료되기 전 다른 작업이 시작될 수 없다.

### 특징

1. **비선점형(Non-preemptive)**: 중간에 멈추지 않고 끝날 때까지 계속 실행
2. **단순성**: 구현이 매우 간단, 자원 관리에 추가 복잡성 없음
3. **평등한 처리**: 모두 공평하게 다루어짐

### 장점

- 간단한 구현 (복잡한 추가 관리 없이 사용 가능)
- 작업 간 차별 없음
- 선정 문제 없음 (예측 가능성 높음)

### 단점

- **긴 대기 시간**: 짧은 작업이 먼저 도착해도 긴 작업이 끝날 때까지 기다려야 함
- **콘보이(Convoy) 효과**: 긴 작업 뒤에 짧은 작업들이 줄지어 지연되는 현상
- **우선순위 고려 없음**: 긴급한 작업이 도착해도 앞선 작업이 끝날 때까지 처리되지 않음

## 라운드 로빈 (Round Robin)

선점형 스케줄링 알고리즘의 대표적인 형태다. 모든 작업에 동일한 **시간 할당량(Time Quantum)** 을 부여하여 순차적으로 처리한다. 할당 시간이 끝나면 작업이 강제 중단되고 대기열 맨 뒤로 이동한다.

공평성, 짧은 대기시간, 빠른 응답성이 특징이다. 다중 작업이 동시 실행될 때 효과적이다.

### 작동 예시

작업 A(6초), B(4초), C(3초)에 시간 할당량 2초를 적용하면:
- 사이클 1: A(2초) → B(2초) → C(2초). 이후 A 4초 남음, B 2초 남음, C 1초 남음
- 사이클 2: A(2초) → B(2초) → C(1초). 이후 A 2초 남음
- 사이클 3: A(2초) 완료

### 장점

- **공평성**: 모든 작업이 동일한 시간 할당량으로 자원 사용
- **짧은 응답시간**: 일정 간격으로 처리되므로 실시간 응답성 요구 시스템에 적합
- **기아 상태 없음(Starvation Free)**: 특정 작업이 자원을 독점 불가
- **실시간 시스템에 적합**: 작업 간 빠른 전환과 연속적 실행 지원

### 단점

- **시간 할당량 선택이 어렵다**
  - 너무 짧으면: 작업 도중 계속 중단 → 전환 비용 ↑ → 시스템 성능 ↓
  - 너무 길면: FCFS와 큰 차이 없어짐
- **문맥 교환 비용 증가(Context Switching Overhead)**: 전환이 잦을수록 오버헤드 발생
- **긴 작업의 처리 지연**: 완료까지 여러 사이클 필요

## 우선순위 스케줄링 (Priority Scheduling)

각 작업에 우선순위를 부여하고, 우선순위가 높은 작업을 먼저 처리하는 스케줄링 알고리즘이다. 작업의 중요도에 따라 실행 순서를 결정한다.

우선순위는 숫자로 표현되며, **보통 숫자가 낮을수록 우선순위가 높다** (`1 > 2 > 3 ...`).

### 선점형 vs 비선점형

- **선점형**: 더 높은 우선순위의 작업이 도착하면 즉시 실행 중인 작업을 중단하고 교체
- **비선점형**: 현재 실행 중인 작업은 끝날 때까지 계속되며, 완료 후 높은 우선순위 작업 처리

### 작동 예시

작업 A(4초, 우선순위 2), B(3초, 우선순위 1), C(2초, 우선순위 3)이 있을 때:
- 모두 동시 도착 → B(우선순위 1) → A(우선순위 2) → C(우선순위 3) 순서로 실행
- 선점형에서 A 실행 중 B가 도착하면 A를 중단하고 B를 즉시 실행

### 장점

- 긴급한 작업 신속 처리 가능
- 유연성: 각 작업에 우선순위를 자유롭게 설정
- 응답 시간 단축: 높은 우선순위 작업이 빠르게 처리됨

### 단점

- **기아 상태(Starvation)**: 높은 우선순위 작업이 계속 도착하면 낮은 우선순위 작업이 무한 대기
- **복잡한 우선순위 결정**: 우선순위를 부적절하게 설정하면 전체 성능 저하
- **우선순위 역전(Priority Inversion)**: 낮은 우선순위 작업이 높은 우선순위 작업을 막는 상황 발생 가능 → 멀티태스킹 환경에서 자원 공유 시 발생. '우선순위 상속' 기법으로 해결

## EDF (Earliest Deadline First)

실시간 시스템에서 주로 사용되는 스케줄링 알고리즘이다. 각 작업이 가진 **마감 시간(Deadline)** 을 기준으로, 가장 먼저 마감이 다가오는 작업을 먼저 처리한다.

마감 시간이 가까워질수록 해당 작업의 우선순위가 높아지는 **동적 우선순위** 방식이다. 선점형과 비선점형 모두 동작 가능하다.

### 작동 예시

작업 A(2초, 마감 8초), B(1초, 마감 4초), C(2초, 마감 6초)가 동시 도착:
- B(마감 4초) → C(마감 6초) → A(마감 8초) 순서로 실행

마감 시간이 동일하면 그 중 하나를 선택하여 실행한다.

### 장점

- **실시간성 보장**: 마감 시간이 가까운 작업부터 처리 → 기한을 놓치는 일이 적음
- **효율성**: 이론적으로 최적의 단일 프로세서 스케줄링 알고리즘으로 간주
- **동적 우선순위**: 상태와 시간에 따라 스케줄링이 유연하게 이루어짐

### 단점

- **과부하 문제**: 시스템이 과부하 상태일 경우 기한을 놓치는 작업 발생 가능
- **실시간 예측의 어려움**: 마감 시간이 계속 변하기 때문에 실시간 성능 예측이 어려움
- **문맥 교환 비용 증가**: 선점형 방식에서 마감 빠른 작업이 도착할 때마다 문맥 교환 발생

## 동적 스케줄링 (Dynamic Scheduling)

작업을 실행하는 도중에 시스템 장애나 작업 요구사항에 따라 **실시간으로 작업의 우선순위나 실행 순서를 변경**하는 스케줄링 방식이다.

시스템의 상태, 자원의 가용성, 작업의 긴급도를 반영하여 유연하게 작업 순서를 조정한다.

### 특징

1. **실시간 우선순위 변경**: 작업 도중이나 작업이 도착할 때마다 상황에 맞게 우선순위 동적 변경
2. **자원 활용 최적화**: 자원의 가용 상태를 실시간으로 반영 → 자원 충돌 방지 및 성능 최적화
3. **실시간 시스템에 적합**: 긴급 작업을 즉시 처리 가능 (예: 자율주행차, 산업용 로봇)
4. **환경 변화 대응**: 자원 상태나 요구사항이 자주 변하는 환경에서 최적 성능 유지

### 장점

- 높은 유연성: 고정된 스케줄링보다 더 효율적
- 실시간 응답 보장: 긴급 작업 즉시 처리 가능
- 자원 최적화: 자원 사용 상황 반영하여 배치

### 단점

- **복잡한 구현**: 실시간 우선순위 조정 및 상태 평가 → 복잡한 알고리즘 + 시스템 부하 증가
- **문맥 교환 비용 증가**: 우선순위 변경이 잦으면 Context Switching 빈번 → 성능 저하
- **우선순위 역전 문제**: 우선순위가 높은 작업이 우선 처리되지 못하는 현상 발생 가능

## 임베디드 시스템 최적화 기술 종합 정리

지금까지 배운 최적화 기법들을 임베디드 AI 시스템 관점에서 종합 정리한다.

| 기술 | 목적 | 장점 | 단점 |
| --- | --- | --- | --- |
| 프루닝 (Pruning) | 모델 경량화 | 연산량 감소, 추론 속도 향상, 메모리 절약 | 과도한 프루닝 시 정확도 손실, 재학습 필요 |
| 양자화 (Quantization) | 메모리·전력 감소 | 모델 크기 감소, 연산 속도 향상, 낮은 전력 | 정밀도 손실, 하드웨어에 따라 성능 다름 |
| 지식 증류 (Knowledge Distillation) | 경량화 + 성능 유지 | 빠른 추론, 원래 성능에 가까운 손실 | 복잡한 학습 과정, 학습 시간 증가 |
| NAS (Neural Architecture Search) | 성능·효율 극대화 | 최적 아키텍처 자동 설계, 맞춤형 모델 | 높은 계산 비용, 탐색 과정 복잡 |
| 스케줄링 (Scheduling) | 병렬·실시간 처리 최적화 | 효율적 순서 결정, 실시간 응답 보장 | Context Switching 오버헤드, 구현 복잡 |

### 최적화된 AI 알고리즘 구현 시 주요 고려사항

**1. 모델 크기 및 메모리 관리**
- 임베디드 보드는 메모리가 제한적 (RAM: 작업 메모리 / ROM: 모델 저장)
- 모델 크기 줄이기: 프루닝, 양자화, 지식 증류
- 메모리 캐싱 활용: 필요한 데이터를 메모리에 캐싱, 중요하지 않은 것은 외부 저장

**2. 연산 성능 최적화**
- 복잡한 딥러닝 모델의 실시간 실행이 어려움 → 연산량을 줄이는 방법 필수
- 경량 모델 사용: MobileNet, Tiny YOLO
- 하드웨어 가속기 활용: GPU, TPU, NPU (엔비디아 Jetson: CUDA, TensorRT)
- 모델 병렬 처리: 여러 연산 동시 수행

**3. 전력 관리**
- 저전력 설계 필수
- 양자화: 8비트 정수 양자화 사용
- 주파수 스케일링: DVFS(Dynamic Voltage and Frequency Scaling) 사용

**4. 실시간 요구사항 및 응답성**
- 실시간 처리 → 추론 최적화 필수
- 스케줄링 최적화 → 긴급한 작업이 제때 처리되도록

**5. 데이터 전처리 및 후처리**
- 전처리: 필터링, 정규화 등을 최소화된 연산으로 처리
- 데이터 압축: 메모리 및 전송 속도 최적화
- 후처리: AI 모델 결과를 실시간으로 후처리 시 연산 자원 최소화 (경량 알고리즘 사용)

**6. 소프트웨어 스택 최적화**
- 경량화된 AI 프레임워크 사용: TensorFlow Lite, PyTorch Mobile

**7. 모델 배포 및 업데이트**
- 배포 시 모델 압축 + 양자화로 크기 최소화
- 지속적인 모델 업데이트

**8. 안정성 및 오류 처리**
- 시스템 오류 발생 대비 오류 복구 메커니즘 필요
- AI 모델의 추론이 중단되지 않아야 함 → 결함 허용 시스템(Fault Tolerant System)
